# 北极星 Demo 剧本 · 三层递进（形态 B）

> **观众**：社区炫技 + 团队/老板展示（双场景，一套剧本两种节奏）
> **核心叙事**：产品本身就是 Agent——不是「SaaS 里嵌了个 AI」，而是**一句话 → 组件 → 组装 → 持续运行**的完整链路
> **时长**：完整版 ~6 分钟 / 社区剪辑版 ~2 分钟（只演第 3 层高潮）
> **前置状态**：3080 实例跑着 dock 0.7.2 + dsh-app 0.3.1（内置 APP 已 seed）

---

## 开场（30 秒）

**镜头**：DSH 空对话 + 右侧收起的 dock。

> "这是我们基于 DeepSeek Harness 搭的 Agent Native 工作台。整个系统的后端是一个本地 PocketBase，插件化、全开源。今天用三层演示它的工作方式。"

---

## 第 1 层 · 内置能力即目录（1 分钟）— 「开箱有什么」

**动作**：展开 dock → APP tab → 点开 OpenLoop（内置 APP）。

**画面**：33 个组件全绿「可固定」状态 + 3 条本地 API。

**台词**：
> "第一层，系统自带的组件库。33 个预设组件——图表、表格、监控、状态——全部注册在后端注册表里。注意：这不是静态清单，是**运行时数据**——每个组件都能被 Agent 读取、调用、改造。"

**Pin 演示**：固定「后端状态」（pb-stats）→ 看板出现实时 uptime / 集合计数 / 数据占用。

> "固定一个「后端状态」——这是它自己的体检卡。"

---

## 第 2 层 · Agent 按需生成（2 分钟）— 「没有的，说一声就有」

**Prompt（现场发）**：

```
帮我创建一个 GitHub 仓库监控 APP：注册一个 app 叫 github-monitor，
然后生成一个面板组件——包含 star 趋势折线图、open issue 数指标卡、
最近 5 条 release 的时间线。面板定义好后注册成组件
（rid: github-monitor:overview，entry 直接内联面板定义），
再注册一个 API 资源（domain api.github.com, path /repos/{owner}/{repo}）。
完成后告诉我组件 ID，我要固定到看板。
```

**等待期台词**（agent 干活的 30-60 秒，指着屏幕）：
> "Agent 正在做三件事：用 panels 的 33 个预设组装面板定义、通过 app_backend 把组件注册进后端、顺手登记了 GitHub API 资源。**注意它没写任何前端代码**——预设就是它的乐高积木。"

**画面重点**（录屏时给特写）：
- agent 完成 → **不等刷新**，APP 页约 15 秒内自动出现 `github-monitor`（P1 轻探的价值瞬间）
- 点开 → 组件「可固定」→ pin → 看板渲染出完整面板

**台词**：
> "注册完成，工作台自动刷新——刚才演示的是**agent 写、用户看**的实时闭环。固定它——一个 GitHub 监控面板，从一句话到这里，不到一分钟。"

---

## 第 3 层 · 用户组装工作台（2 分钟）— 「你的地盘你做主」

**动作序列**（手速演示，无 prompt）：

1. rail 拖宽到中枢态 → **新增看板页**「项目监控」
2. 把刚生成的 GitHub 面板 + 内置 pb-stats + db-browser **拖拽布局**（自由摆放、调大小）
3. db-browser 里选 `components` 表 → 关键词搜 `github` → 现场展示「注册表里真有这条数据」
4. 回第 1 个看板页 → 双击 tile 标题改名（别名功能）

**台词**：
> "第三层，用户接管。多个看板页、自由拖拽、组件来自不同 APP 混排——左边是我刚才生成的 GitHub 监控，右边是系统自带的数据库浏览器。**这就是 Dock 的意义：Agent 生成原料，用户组装自己的工作台。**"

---

## 高潮收尾 · 自愈彩蛋（30 秒，社区版压轴）

**动作**：终端 `pkill -f pocketbase` → 镜头切回浏览器。

**台词**：
> "最后——把后端杀了。"
> （等 2-4 秒，watchdog 自动重启）
> "它自己回来了。重启次数 +1，数据一分不丢。整个系统的存储、注册表、自愈，都跑在这个本地小后端上。**这就是 Agent Native：不依赖某个云服务活着，它自己会活。**"

---

## 双场景节奏表

| 环节 | 完整版（团队/老板） | 剪辑版（社区） |
|---|---|---|
| 开场 | 30s 全讲 | 跳过 |
| 第 1 层 | 1 min | 5s 快剪（目录滚一遍） |
| 第 2 层 | 2 min 全程 | **60s 核心**（prompt → 自动出现 → pin） |
| 第 3 层 | 2 min 拖拽组装 | 30s 快剪 |
| 自愈彩蛋 | 30s | **30s 保留**（社区最爱看这个） |

---

## 验收清单（正式录制前自测）

- [ ] 内置 OpenLoop APP 在 APP 页（33 组件全可 pin）
- [ ] 第 2 层 prompt 全链路 < 90 秒（agent 生成 + 注册 + 15s 内自动出现）
- [ ] pin 的 GitHub 面板渲染正确（折线图 + 指标 + 时间线）
- [ ] 拖拽布局流畅（多 tile 混排无卡顿）
- [ ] db-browser 搜 `github` 能看到注册的组件记录
- [ ] pkill 后 ≤5s 自愈、restarts+1、看板数据完好
- [ ] **加分项**：seedBuiltinApp 的内置 APP 被改名后重启**不被覆盖**（幂等语义）

## 已知风险与规避

| 风险 | 规避 |
|---|---|
| agent 生成面板超时（模型慢） | 预跑一遍热身；演示时用「等待期台词」填场 |
| GitHub API 未配凭据 | 第 2 层面板用静态演示数据（api.github.com 公开接口无需 key），提前 curl 验证 |
| pkill 后 watchdog 恰好熔断 | 演示前 `backend_health` 确认 restarts=0；只 kill 一次 |
| 15s 自动刷新在录屏里显得慢 | 台词覆盖："约 15 秒内自动出现"——或剪辑加速 |

## 需要的开发准备（本剧本暴露的 gap）

1. **GitHub 面板的数据绑定**：panels api 绑定只支持公网 https（api.github.com 可用）——第 2 层 prompt 里让 agent 加 `data` 绑定即可，无需开发
2. **无**——其他全部能力已落地（三层 + 自愈全部真机可用）
